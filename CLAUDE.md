# hookah-mixer-core — контекст для AI-агента

Ядро сервиса Hookah Mixer: база знаний о сочетаниях ароматов для кальяна (`data/`) и движок подбора миксов (`src/`).
Клиент — статическое веб-приложение `~/dev/pet/hookah-mixer` (GitHub Pages, https://demansh.github.io/hookah-mixer/),
оно получает ядро копированием `dist/` скриптом `tools/sync-core.sh`. Полное описание API, форматов данных
и процессов — в `README.md` этого репозитория; держи его актуальным.

## Как устроен продукт (коротко)
Гость кальянной описывает настроение («свежие тропические фрукты с холодком», «Бледный Петербург», «овсянка»)
и получает 3 микса из 3–4 ароматов с процентами — без брендов и табаков, микс называют кальянщику.
Уровни: classic (классика с изюминкой), balanced (эксперимент), bold (смелое сочетание).
Два входа: текст `recommend({ query })` и структурный выбор `recommendSelection({ concepts, flavors, properties,
required, excluded })` с весами (для интерфейсов на тапах); оба сходятся в одном профиле.
Пайплайн: `text.js` (токены, словоформы) → `profile.js` (разбор запроса, образы, «без X») → `selection.js`
(проверка выбора, построение профиля из вкладов) → `mixes.js` (пул
соседей по графу, перебор комбинаций, оценка) → `recommend.js` (уровни, страницы, зерно, случайный режим) →
`shares.js` (проценты). `mix-link.js` — кодирование миксов в ссылки и строгий разбор.

## Пользователь и правила работы (обязательно)
- Общение и документация — на русском.
- Данные (`data/`) пишет агент; пользователь не разбирается в табаках и даёт только отзывы о вкусе и о странных
  выдачах. Не проси его размечать данные.
- **Никаких комментариев в коде** (включая docstrings). **Unit-тестов нет** — качество держится на валидаторе
  и диагностике (`npm run check`). Не предлагай тестовые фреймворки.
- Агент **не коммитит и не пушит**: в конце даёт команду `git add -A && git commit -m "..." && git push`.
  Локальный `user.email` репозитория — `demansh17@gmail.com`.
- **Id ароматов не переименовывать и не удалять** — на них ссылаются избранное и отправленные ссылки у пользователей.
- Ядро не зависит от браузерного интерфейса: никакого DOM, i18n интерфейса, эмодзи-мастера — это приложение.
  Публичный API — только `src/index.js`; всё остальное внутреннее.
- Планы и исследования сохранять в `~/ai/hookah-mixer/` (≤100 строк, ≤120 символов, разделы: запрос
  пользователя, краткое содержание, основная часть).

## Команды
```bash
npm install                 # один раз (зависимость yaml для инструментов)
npm run validate            # проверка data/ — всегда 0 errors
npm run build               # validate + сборка dist/ (data/*.json, js/, VERSION)
npm run check:words         # регрессия словоформ — эталон 83/83 и 12/12
npm run check:sweep         # все ароматы/свойства/фразы образов + выбор — эталон 889 запросов + 223 выбора, 0 проблем
npm run check               # всё вместе
npm run diagnose -- --pages=3 "запрос"     # разбор конкретного случая
npm run diagnose -- --seed=12345 "запрос"  # воспроизвести выдачу пользователя (зерно из ?debug=1 приложения)
```
Эталонные цифры обновлять в этом файле и README при изменении данных.

## Скиллы (`.claude/skills/`)
- `fix-query-handling` — запрос не распознаётся, распознаётся не так, пустая или однообразная выдача, пропадает
  уровень. Классы ошибок и где их чинить.
- `add-knowledge` — добавить аромат, пары, образ или образ-категорию; правила разметки.
- `release-to-app` — выпустить версию ядра и подключить её в приложение (версия, CHANGELOG, build, sync).
