# Пополнение базы знаний

Данные пишет агент: пользователь не размечает, он сообщает «нет аромата X» или «X + Y не зашло». Правила
проекта — в `CLAUDE.md`. Форматы — в `README.md`, раздел «База знаний».

## 0. Сначала проверь, нужен ли новый аромат
- Есть ли он под другим названием? Ищи по синонимам: `grep -i "слово" data/tags.csv`.
- Выражается ли он сочетанием существующих? «Облепиховый чай» = `sea_buckthorn` + `black_tea` → это образ, не аромат.
- Солёная/мясная еда (колбаса, сыр) кальянными вкусами не бывает — не добавлять (решение пользователя).

## 1. Аромат (`data/tags.csv`)
- `id`: латиница, `snake_case`, навсегда (не переименовывать).
- `category`: только существующие (иначе нужна строка для каждой пары категорий в `category_affinity.csv`).
- `role`: base (40–55%) / accent (15–30%) / support (10–20%); `cooling` — только холодок.
- `intensity` 1–5: насколько забивает другие (анис, гвоздика = 5 → доля ≤15%).
- `sweet`/`sour`/`fresh` 0–5; `ru`/`en`; синонимы через `|` — **другие слова**, не словоформы
  («ромашковый чай», «camomile»), формы движок понимает сам; описание 3–12 слов про ощущение, без брендов.

## 2. Пары (`data/pairings.csv`) — 15–30 на новый аромат
- `affinity` −1..1: 0.8–0.9 классика вкуса, 0.5–0.7 хорошо, 0.3–0.4 допустимо, <0 конфликт (−0.5 нельзя).
- `familiarity`: classic — «предлагают везде, приелось»; known — известное; rare — неожиданное, но удачное.
  Новизна выдачи держится на rare — не помечай всё known.
- Пояснение RU/EN обязательно для rare и для классики; одна короткая фраза «почему работает».
- Обязательно конфликты: с холодком, кофе, огурцом и т. п., где уместно.
- Отзыв пользователя «X + Y не зашло» → понизить affinity (или сделать конфликтом) и отметить в пояснении.

## 3. Образы (`data/concepts.yaml`)
- 2–5 фраз RU, 1–3 EN, имена собственные с заглавной (сравнение регистронезависимое); первая фраза — самая
  понятная (она показывается на чипе, если `chip: true`).
- `tags`: 3–6 ароматов/свойств, веса 0.1–1; `avoid`: явные противоречия.
- Образ-категория (`category-*`) — все ароматы категории с равными весами (0.6), чтобы не было «везде манго».
- `chip: true` — только конкретные понятные гостю вещи (группы вкусов, напитки, десерты), не города и настроения.
- Фразы не должны дословно совпадать с абстрактными запросами `data/eval/queries.jsonl` (валидатор проверит).

## 4. Проверить
```bash
npm run validate && npm run build
npm run diagnose -- --pages=2 "новый аромат" "фраза образа"
npm run check:words      # добавь в tools/wordforms.json словоформы нового аромата/образа
npm run check:sweep
```
Обнови объёмы данных в `CLAUDE.md`, `README.md` (таблица проверок) и запись в `CHANGELOG.md`, затем
`release-to-app`.
