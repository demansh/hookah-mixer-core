# Исправление ошибок обработки запросов

Пользователь присылает запрос и что пошло не так (иногда — зерно из `?debug=1` приложения). Найди класс ошибки,
исправь его **для всего класса запросов**, а не для одного слова, и докажи, что ничего не сломалось.
Правила проекта — в `CLAUDE.md` (без комментариев в коде, без unit-тестов, не коммитить, id не переименовывать).

## Где искать причину
- `src/engine/text.js` — словоформы: общий префикс + хвост обязан быть окончанием (`WORD_ENDING_PATTERN`),
  отступ окончания назад (`ENDING_BACKOFF`), короткие слова на -й/-ь (`SOFT_FINAL_LETTERS`), `removeSpans`.
- `src/engine/profile.js` — самое длинное совпадение с фразами образов и названиями/синонимами; частичное
  совпадение со словом фразы образа (×0.5, слово не из >`PARTIAL_MAX_CONCEPTS_PER_TOKEN` образов); «без X»;
  `required` (≤`MAX_REQUIRED_FLAVORS`), `contradictions`, `spans`.
- `src/engine/selection.js` — выбор (`recommendSelection`), его проверка и общий построитель профиля для текста
  и выбора: веса образов, свойств, ароматов, `required`, `excluded`, `avoid`. Жалоба из лабы на тапах —
  воспроизводи через `npm run diagnose -- --selection='{…}'`.
- `src/engine/mixes.js` — пул (соседи ≥0.5; если <`MIN_POOL_SIZE` — добор по матрице категорий; семена от свойств;
  холодок приводит соседей, только если он один), ограничения комбинаций, оценка.
- `src/engine/recommend.js` — уровни, разные основы, страницы, встряска оценок по зерну, случайный режим.
- Данные: `data/tags.csv` (синонимы!), `data/concepts.yaml` (образы, категории), `data/pairings.csv`.

## Шаг 1. Воспроизвести
```bash
npm run build
npm run diagnose -- --pages=3 "запрос пользователя"
npm run diagnose -- --seed=12345 "запрос"     # если пользователь дал зерно
```

## Шаг 2. Определить класс (разобранные случаи)
| Симптом | Пример | Причина | Исправление |
|---|---|---|---|
| не понял обобщающее слово | «алкоголь», «орехи» | нет образа категории | образ `category-*`, ароматы с равными весами |
| не понял аромат | «чили» | нет синонима | синоним в `tags.csv` (другое слово, не словоформа) |
| не понял устойчивую фразу | «бабушкино варенье» | нет образа | новый образ, 2–5 фраз RU, 1–3 EN |
| не понял фразу из общих слов | «вечер у бабушки» | слова из >2 образов отбрасываются | норма; при частых жалобах — точный образ |
| ложное совпадение | «колбаса» → кола, «роман» → ром | хвост не окончание | `WORD_ENDING_PATTERN`; **не ослаблять** |
| словоформа не распознана | «тропическими», «чаем» | префикс съел гласную / стем на -й | `ENDING_BACKOFF`, `SOFT_FINAL_LETTERS` |
| не то слово победило | «сливочное» → слива | короткое слово выигрывало | нормировка на длину (есть) |
| профиль раздут частичными совпадениями | «летний вечер на террасе» | общее слово | точный образ |
| понял, но миксов нет | «энергетик» | узкий пул, несогласованные лимиты долей | `MIN_POOL_SIZE`, `mixLimits(requiredIds)` |
| только свойство | «пряности», «горчинка» | нет семян | `expansionSeeds`, образ категории |
| одна основа во всех карточках | «тропики» → везде манго | неравные веса | правило разных основ, равные веса в категориях |
| уровень пропал на перегенерации | «гранат» | фильтр уровня исчерпан | подходящие + остальные; лимит соседей классики при ≥2 семенах |

Одно слово/образ — правка данных; класс запросов — правка движка. Сомневаешься — сначала данные.

## Шаг 3. Исправить и доказать
```bash
npm run validate && npm run build
npm run check:words      # добавь новый случай в tools/wordforms.json: shouldMatch или shouldNotMatch
npm run check:sweep
npm run diagnose -- --pages=3 "исходный запрос"
```
Каждый разобранный случай — в `tools/wordforms.json`, чтобы ошибка не вернулась. Обнови эталонные цифры в
`CLAUDE.md` и `README.md`, если изменились. Затем — скилл `release-to-app`, чтобы исправление дошло до приложения.

## Шаг 4. Отчитаться
Причина (класс), что изменено, цифры проверок, результат на исходном запросе, команда коммита.
